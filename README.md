# Binary Fractal Viewer

Минималистичный полноэкранный просмотрщик матрицы `B(n,k) = (n >> k) & 1`.
TypeScript, Vite, Canvas 2D. Чёрный фон, белые единицы, три кнопки.

## Локальный запуск

Нужен Node.js 24 LTS.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite, обычно `http://localhost:5173`.
Для телефона в той же локальной сети используйте адрес Network из вывода Vite.

```sh
npm test
npm run build
npm run preview
```

`dist/` — готовый статический сайт. Открывайте через HTTP, а не `file://`:
браузеры ограничивают загрузку ES-модулей из локальных файлов.

## Управление

- Колесо мыши или щипок трекпада: плавный масштаб относительно курсора.
- Перетаскивание мышью / одним пальцем: перемещение.
- Два пальца: масштаб и перемещение относительно центра жеста.
- `+` / `−`: масштаб относительно центра экрана. Удержание экспоненциально
  ускоряет движение; примерно за 22 секунды можно пройти миллион десятичных порядков.
- `0`, `Home` или кнопка со стрелкой: начальный вид. Стрелки клавиатуры: перемещение.
- `Escape`, потеря фокуса, отмена указателя: остановка текущего управления.

Для воспроизводимой загрузки сверхглубокого масштаба доступны ссылки:

```text
http://localhost:5173/#scale=10^-1000
http://localhost:5173/#scale=10^-1000000
http://localhost:5173/#scale=10^-1000000000000000000000000000000
http://localhost:5173/#scale=10^1000000
```

Это параметры ссылки, дополнительных панелей в интерфейсе нет.

## Математическое соответствие

Строка `n=0` находится сверху. Строки идут вниз по возрастанию. Младший разряд
`k=0` находится справа, более старшие — левее. Отрицательных строк и разрядов нет.
При обычном масштабе клетки квадратные и соответствуют исходной формуле.

**Принципиальная особенность:** равномерное отдаление этой матрицы не создаёт
изотропно самоподобного фрактала. Количество ненулевых столбцов в первых `N`
строках растёт только как `log₂ N`. Сохранять видимую структуру при произвольно
сильном отдалении и одновременно сохранять исходную евклидову геометрию нельзя.
Поэтому ниже одного экранного пикселя на строку просмотрщик плавно переходит к
структурным координатам. Это явно определённая смена проекции.

Для любого целого `q ≥ 0` и `k ≥ q`:

```text
B(n,k) = B(floor(n / 2^q), k-q)
B(2^q · m, q+j) = B(m,j)
```

Старшие разряды одинаковы во всём блоке из `2^q` последовательных строк.
Структурная клетка точно представляет такой блок и один исходный старший разряд.
Здесь нет случайных данных, подмены треугольником Серпинского или усреднения
бесчисленного количества клеток в серую заливку.

Пусть `L = log₂(s)`, где `s` — пиксели на исходную строку:

```text
r = max(0, -L)
q = floor(r)
t = r-q
original bit = q+j
coarse row = floor(n / 2^q)
horizontal cell interval = [t-j-1, t-j]
column width = max(1, 2^L) screen pixels
```

Высота структурной строки равна `2^(L+q)` и находится между 0,5 и 1 пикселем.
При приближении к следующему уровню самый младший видимый столбец плавно исчезает;
все оставшиеся столбцы и интервалы единиц совпадают на границе уровней.
Полупрозрачность используется только для ухода этого одного столбца.
При возвращении к обычному масштабу младшие разряды восстанавливаются.

По вертикали сохраняется исходная координата строки под курсором. По горизонтали
в структурном режиме сохраняется координата проекции `k-r`, поэтому исходный
номер разряда меняется вместе с уровнем. Это необходимо для структурного просмотра;
данный режим не следует выдавать за обычное равномерное масштабирование плоскости.

## Точность и производительность

- Масштаб: фиксированная дробь логарифма с шагом `2^-48` октавы и целой частью
  `BigInt`. Нет программного минимума или максимума масштаба.
- Координаты: точные суммы двоичных чисел в разреженных сбалансированных блоках
  по 128 бит. Показатели блоков также `BigInt`. Между `1` и `2^(-10^100)`
  не выделяется массив из `10^100` нулей. Малые смещения не стираются.
- Десятичные показатели переводятся в логарифм с растущей точностью Decimal.js.
  Миллион порядков не означает создание числа с миллионом цифр.
- Жест хранит исходную точку привязки и пересчитывает положение из неё,
  предотвращая накопление погрешности при последовательных событиях.
- Рендерер вычисляет интервалы единиц по периодам разрядов. Число операций
  зависит от размеров экрана и занятых блоков координат, а не количества
  скрытых строк. Полная матрица никогда не создаётся.
- Canvas 2D выбран потому, что даже полный кадр требует лишь нескольких сотен
  прямоугольников. Точные большие числа остаются на CPU; перевод в числа с
  плавающей точкой происходит только для локальных экранных расстояний.
- Общие границы округляются одинаково до физических пикселей; между соседними
  белыми клетками не появляются швы от повторного альфа-смешивания.
- Отрисовка запрашивается только при изменении вида. В покое нет цикла кадров.

Бесконечность не означает бесконечную память: ресурсы устройства конечны.
История перемещений с новыми независимыми разрядами может увеличивать число
занятых блоков. Приложение не обрезает эти разряды ради фиксированного бюджета.
Различие между точной арифметикой сохранённых двоичных координат и конечной
точностью входных событий/дроби логарифма также существенно.

## Проверки

`npm test` проверяет:

- сопоставление разреженной арифметики с независимым плотным BigInt-эталоном;
- исходные клетки и тождество структурных блоков;
- масштабы `10^-1000`, `10^-1000000`, `10^1000000`, вплоть до
  десятичного показателя `-10^100`;
- сохранение привязки, 20 000 изменений зума, обратные перемещения;
- непрерывность на границах уровней и видимую границу клетки при огромном приближении;
- колесо, Ctrl-wheel, разные единицы wheel, перетаскивание, щипок,
  перемещающийся центр, добавление/удаление пальцев, отмену, ускорение, сброс;
- программную растеризацию настольного/мобильного размера и ограниченность
  числа рисуемых прямоугольников.

Изображения и результаты CPU-замера записываются в `artifacts/`.
Тесты событий выполняются в Happy DOM, изображения — через нативный Canvas.
**Это не проверка настоящего браузера, GPU или физического мультитача.**
Дополнительно выполнена проверка в настоящем Chromium через Playwright (см. ниже).
Проверка физических сенсорных устройств и Safari остаётся отдельной задачей.

## Обновление управления и браузерная проверка

Клетки теперь непрерывно уменьшаются до одного CSS-пикселя. Только ниже этого
порога включается структурная проекция старших разрядов. Поле «Начальное число»
принимает неотрицательные десятичные целые через BigInt, сохраняет масштаб и
устанавливает введённую строку у верхнего края. Сброс сохраняет выбранное число.

В окружении установлен Chromium через Playwright. Firefox 159 завершал процессы
рендеринга из-за ошибки shared memory. Chromium работает в отдельном headless
профиле с параметрами совместимости, указанными в `scripts/browser-check.mjs`.
После запуска `npm run dev` выполните `node scripts/browser-check.mjs`: проверяются
колесо, ввод большого числа, отсутствие ошибок JavaScript и чередование строк
высотой один пиксель; скриншоты сохраняются в `artifacts/browser-*.png`.
